01

Words

Keywords versus functions

KEYWORDS vs FUNCTIONS — the bracket test.

Both are reserved, built into Python (shown purple in syntax highlighting) — def, if, for, global, return are all keywords. But keywords and functions behave differently, and there's a reliable tell: functions are called using round brackets (), because they can take input through those brackets — print(x), len(my_list). Keywords are instructions about code structure itself, not something you call with input — they never take brackets. return some_value just needs a bare value sitting after it; no brackets required or standard, unlike print(some_value).

Test: needs () to work → function. No brackets, just a bare word followed by whatever it operates on → keyword.

The values you pass in through those brackets have a name: arguments. print("hello") passes one argument; range(1, 6) passes two. Keywords do not take arguments, because you are not calling them — return total is not passing total in to anything, it is a structural instruction with a value after it.

IMPORTANT CORRECTION — the bracket test works one way only.

The test is reliable in this direction:

Takes () and passes values in → it's a function.

It is not reliable in reverse. "No brackets → keyword" fails, because several keywords are followed by a value and look exactly like the thing the test says they aren't:

not is_member # keyword, no brackets, takes a value "y" in answers # keyword, no brackets, takes two values del tools[0] # keyword, no brackets, takes a value return total # keyword, no brackets, takes a value

And it fails in the other direction too — brackets can appear after a keyword for grouping, which is not a call:

return (price * 2) # brackets are maths grouping, not a call if (a and b): # same — grouping, allowed but unnecessary

The reliable test instead — what is it for?

  • A keyword is part of the language's grammar. It's a word Python's parser recognises structurally: it opens a block, or directs the flow, or modifies a statement. You cannot rename it, reassign it, or pass it around.
  • A function is a value that happens to be callable. It has a name that points at it, exactly like a variable does, and that name can be reassigned or passed to something else.

That last point is the definitive one, and you have already met it in Chapter 11 (Decorators): @add_lights works precisely because decorate_tree is a name pointing at a function value, and the decorator repoints it. No keyword can be handed around like that.

The practical check, if you're unsure of a specific word: try assigning it to something.

x = print # fine. print is a value. x = if # SyntaxError. "if" is grammar, not a value.

The complete keyword list, so it can be settled by looking. There are only 35, and you've met most of them:

False None True and as assert async await break class continue def del elif else except finally for from global if import in is lambda nonlocal not or pass raise return try while with yield

Anything not on that list is not a keyword. print, len, input, int, range, enumerate are all absent from it — they're built-in functions, which is a different category despite also being coloured distinctively by most editors.

Why the syntax highlighting misleads. Editors often colour keywords and built-in functions similarly, which is what makes them look like one group. They aren't: keywords are the grammar of the language, built-ins are just functions that happen to be available without importing anything. The proof is that you can (though shouldn't) reassign a built-in — print = 5 is legal and will break your program — whereas if = 5 is a syntax error.

Methods versus functions

Methods vs functions — both are instructions, but attach differently.

A method is attached to a specific object with a dot: .append(), .lower(), .strip() all mean "do this action to the thing immediately on my left." A function stands alone and takes its input inside brackets instead: enumerate(members), int(input(...)). Both do a job, neither is "more powerful" than the other — the distinction is just how each one receives what it's acting on.
