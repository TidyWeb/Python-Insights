Why f-strings are worth the attention

Of everything in this reference, this is the chapter I would ask you to read even if you came here for something else.

F-strings are the one that opened the door for me. They were the first place where the whole boxes-inside-boxes idea stopped being an abstraction and became something I could watch happening on a single line — and once it did, a good deal of the rest of Python stopped feeling like a pile of unrelated rules and started looking like one idea repeated.

I had been treating string formatting as a cosmetic thing, a way of tidying up output. It is not. It is the same reaching-into-containers action as everything else, just done somewhere you can see it clearly.

What an f-string actually is

Put an f immediately before a string and Python will treat any curly braces inside it as live instructions rather than as ordinary characters.

name = "Ravi" print(f"Good morning {name}")
Good morning Ravi

Without the f, that line prints the word {name} exactly as typed, braces and all. The f is what makes the braces mean something.

A box with windows cut into it

Picture an f-string as a box with windows cut into it. The ordinary text is the box. Each {} is a window. Through each window you reach into some other box and pull out whatever is inside, and what you pulled out appears in the gap.

The sentence stays fixed. The values arriving through the windows change on every run.

The realisation — what goes in the braces is not new syntax

This is the part that unlocked it. Whatever you would write on its own line to get at a value is exactly what goes inside the braces. Nothing is added. Nothing is special.

member = {"name": "Ravi", "orders": 3} # the long way - reach out here, then print found = member["name"] print(found) # the same reach, done inside the window instead print(f"{member['name']}")
Ravi Ravi

Both print the same thing. The second is not a shortcut with its own rules — it is the identical lookup, relocated inside the braces. The braces move where the reaching happens. They do not change how it works.

Why this matters beyond formatting. Every f-string you write is one more repetition of reach into a container and pull a value out — the same action used by list indexing, dictionary lookup, slicing and function calls. The container changes. The action never does. That is why practising f-strings quietly teaches you everything else.

The two entries below are the practical consequences: how to control the way a value looks once it arrives, and the proof that every possible source behaves identically.

Format specifiers

A format specifier like .2f goes inside the same curly braces as the variable it's formatting — never outside them.

Inside an f-string, {} is one self-contained instruction: variable name, then a colon, then the formatting code, all sealed inside that one pair of braces. It only affects what is inside that specific pair; plain text sitting outside the braces is untouched.

The anatomy of one pair of braces.

total = 3.4 print(f"That will be £{total:.2f} please")
That will be £3.40 please

Reading the braces from the inside out:

  • total — the thing to fetch
  • : — the divider. Everything left of it is what, everything right is how it should look
  • .2f — show it as a decimal number to two places

The £ and the word please sit outside the braces, so .2f has no effect on them whatsoever. Without the specifier you would get £3.4 — correct arithmetically, wrong for money.

The specifiers worth knowing. There are many; these four cover almost everything you will need.

value = 1234.5678 rate = 0.075 print(f"{value:.2f}") # 1234.57 two decimal places print(f"{value:,.2f}") # 1,234.57 thousands separator too print(f"{rate:.0%}") # 8% as a percentage print(f"{value:>12.2f}") # 1234.57 right-aligned in 12 spaces

That last one is how you line figures up in a column when printing a table.

The trap: breaking the string in half.

An f-string is one continuous piece of text from its opening quote to its closing quote. The braces go inside that unbroken string. A common first attempt closes the string early:

print(f"£ "{total} " Delivery is free")
SyntaxError: invalid syntax

Read what those quotes actually do. The first " opens a string and the second " closes it — so {total} is now sitting outside any string at all, and then a third " opens a new one. Three fragments where there should be one.

The fix is to leave the string whole and let the braces do the work from inside it:

print(f"£{total:.2f} Delivery is free")
£3.40 Delivery is free

The habit that prevents it. Write the sentence first, in full, as ordinary text. Then go back and replace the changeable parts with braces. That way the string is never broken open, because you never had two of them.

F-strings pull from any source

F-strings pull from any source the same way — loop variable, dictionary lookup, or an enumerate pair — same {} mechanism every time.

The claim, and the proof.

If the braces really are just a relocated lookup — as the opening of this chapter argues — then it should not matter what you put in them. Anything that produces a value should work, with no extra rules to learn for each kind.

That is exactly what happens. Here are six completely different sources in one block:

tools = ["hammer", "saw"] member = {"name": "Ravi", "orders": 3} price = 3.4 for i, tool in enumerate(tools, start=1): print(f"{i}. {tool}") # 1. hammer print(f"{member['name']}") # Ravi dict lookup print(f"{member['orders'] * 2}") # 6 a calculation print(f"{member['name'].upper()}") # RAVI a method print(f"{len(tools)}") # 2 a function print(f"{price:.2f}") # 3.40 with formatting

Six different sources, one mechanism. Evaluate whatever expression sits in the braces, drop the answer into the sentence.

The quote trap, which follows directly from this.

Because the braces contain real code, a dictionary lookup inside them needs its own quotes — and those cannot be the same quotes holding the string together, or the string ends early.

print(f"{member["name"]}") # breaks - the string closes at "name print(f"{member['name']}") # works - single quotes inside double

Double quotes outside, single quotes inside. This is the same nesting rule as brackets, applied to quotation marks.

What to take from this. There is no list of "things you are allowed to put in an f-string" to memorise, and never was. If it produces a value, it goes in the braces. That is the whole rule, and it is why this is one of the few corners of Python where you can stop checking and simply write what you mean.
