Python · the whole shape

Four things.That is all it does.

Python is taught as a pile of separate topics with names nobody explains — syntax, control flow, iteration, scope. Underneath, a program only ever does four things. This page names the territory properly, so the rest has somewhere to sit.

A note on where this came from

I put this together from notes I was taking as I went, while struggling to work out how Python was actually structured and what the concepts underneath it were.

Nearly every tutorial I found dived headfirst into syntax — the ubiquitous hello world — and that was no good to me. I needed to understand things from a higher level first: what the pieces are, what they are called, and how they relate to one another. Without that, the individual lessons had nothing to attach themselves to and slid straight back out again.

So I wrote the thing I wanted to have been given. I hope it helps you as much as it has helped me.

02

The whole language, briefly

What a program actually does

Every program ever written does some combination of four things. Every topic on any Python course is a detail of one of these. If a lesson ever feels unmoored, the useful question is: which of the four is this about?

Hold

Keep a value somewhere so you can use it later — one value, or a whole collection of them.

Proper names: variables, data types, data structures.

Decide

Look at something and choose a path. Do this, or that, or the other, depending on what is true.

Proper names: conditionals, branching, control flow.

Repeat

Do the same job once for each of many things, or keep going until something tells you to stop.

Proper names: iteration, loops.

Package

Write a set of steps once, give it a name, and use it whenever you need it.

Proper names: functions, parameters, scope.

Everything else — slicing, f-strings, decorators, modules — is a refinement of one of those four. Nothing is a fifth thing.

Why this is worth holding onto. Courses tend to teach the four in order and then never name them again, so it stops being obvious that a lesson on dictionaries and a lesson on lists are the same idea wearing different clothes. They are both Hold.

03

The one idea underneath all of it

Boxes inside boxes

Python spends its entire life doing two things: putting things inside other things, and reaching back in to pull them out again. Almost every difficulty in the language is one of those two operations wearing a disguise.

This is worth meeting early, because once you see it you stop learning a dozen unrelated topics and start recognising the same shape in new clothes. A list holds dictionaries. A dictionary holds values. An if block holds the lines that belong to it. A function holds its own private variables. A decorator holds an entire function inside another one. Same idea, five times over.

Putting in — the nesting

A parcel can hold smaller parcels, which hold smaller ones still. Python has no limit on how deep this goes, and no rule that things at the same level must match.

Here is a coffee shop menu. It is one list, and inside that list sit three dictionaries — one per drink. Each dictionary holds three labelled values: a name, a price, and whether the drink is served hot. This is the code that builds it.

menu = [ {"name": "Latte", "price": 3.10, "hot": True}, {"name": "Mocha", "price": 3.40, "hot": True}, {"name": "Iced tea", "price": 2.60, "hot": False} ]

Notice the two bracket types doing different jobs. The outer [ and ] build the list. The inner { and } build each dictionary. Drawn as boxes, that same code looks like this.

Three levels are visible there: the big box (a list), the medium boxes inside it (dictionaries), and the labelled slips inside those (the actual values). The list is only a wrapper — it holds no detail of its own. All the richness is in the dictionaries.

Taking out — the address label

To reach a value you write its address, and each bracket is one more line of that address, narrowing as it goes. Exactly like addressing an envelope: country, then city, then street, then house number.

Say you want just one thing from that menu — the name of the second drink. You cannot ask for it directly. You have to say which box, then which slip inside that box. Two steps, written as two brackets on one line.

print(menu[1]["name"]) # Mocha

Read that left to right: menu is the whole thing, [1] opens the second dictionary, ["name"] takes the slip labelled name. Each bracket narrows the target, like this.

Read it left to right, outside in. Start with the biggest container and work inwards, one bracket at a time. Each bracket opens one more box. You cannot skip a level, and you cannot stay inside a box between lines — every line writes the full address again, or parks the box in a variable first.

The same shape, five more times

Once you are looking for containers, they turn up everywhere — including in places that have nothing to do with data.

Where you meet itWhat the box isWhat is inside
Lists and dictionariesThe collectionValues, or more collections
IndentationAn if or for blockThe lines that belong to it — indentation is the box wall
Nested callsint(input("How many? "))A box inside a box. The inner one opens first

Indentation is the one worth pausing on, because it does not look like a container at all. But it is: the indented lines under an if are inside it, and the un-indented line after is outside. When a total prints three times instead of once, that is a box-boundary problem — the print is inside the loop when it should be outside.

The sentence to carry with you. Building a box uses one kind of bracket. Reaching into a box uses another. Nearly every bracket question in Python is really the question — am I making something, or am I opening something?

05

The distinction underneath everything

Expressions and statements

This one is almost never taught, and it quietly explains a dozen things that otherwise look like arbitrary rules.

Expression

Produces a value

Ask it a question and you get something back. It can be put anywhere a value could go — inside brackets, after an =, inside another expression.

2 + 2 len(tools) menu[3]["name"] price * 0.9 name.upper()

Statement

Does something

It performs an action or directs the flow. It does not produce a value, so it cannot be tucked inside anything else.

total = 5 if price > 10: for tool in tools: return total import math

Why this matters. It is the reason print(len(tools)) works but print(if x) is a syntax error. len(tools) is an expression — it produces a value, so it can sit inside print(). if x is a statement — it produces nothing, so there is nothing for print() to receive.

The same distinction explains why you can nest int(input("How many? ")) — both are expressions, each producing a value for the next one out to work on. And it is the real reason behind the keyword-versus-function difference in Chapter 03: functions are expressions, keywords are grammar.

The quick test. Could this sit on the right-hand side of an = sign? If yes, it is an expression. x = len(tools) is fine. x = if price > 10 is nonsense.

06

Reading the red text

The three kinds of error

Errors feel like one undifferentiated wall of red. They are not. There are three families, they fail at different moments, and knowing which one you are looking at tells you where to go hunting.

Family one · before anything runs

SyntaxError

Python could not read your file. It never got as far as running a single line — not even the correct ones above the mistake.

Usually a missing colon, an unclosed bracket, or a stray character. The line number it reports is reliable.

Friendly, oddly. Nothing ran, so nothing half-happened.

Family two · while running

NameError, TypeError,
KeyError, IndexError

Python read the file fine and started running it, then hit something impossible partway through.

A name that does not exist. A number where text was needed. A dictionary key that is not there. A list position past the end.

Everything above the failure already happened.

Family three · no error at all

Wrong answer

The program runs start to finish and gives you a number. The number is wrong.

Python is satisfied, so it says nothing. Discount applied to everyone. Total off by one. Loop that never ran.

The hardest kind — nothing tells you it happened.

The one habit worth building. Read the last line of the error first — that is the error type and message. The lines above are the path Python took to get there, and are mostly noise until you know what you are looking for.
